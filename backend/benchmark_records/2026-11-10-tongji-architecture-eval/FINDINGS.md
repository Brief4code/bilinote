# 本轮结果解读

本轮所有回答和裁判请求均发往 Tongji，模型为 `DeepSeek-V4.1-Flash`。使用 5 段视频、40 道固定题；每配置每预算运行一次，没有独立留出集。大模型评分是同模型自评，尚未经人工校准。

## 这次新增对照揭示了什么

1. **纯 Agent 本身也能达到很高的规则通过率。** 标准预算下纯 Agent 与 RAG + Agent 都是 40/40；自评分别为 37/40 和 38/40。不能把主动查询的全部收益都归给初始 RAG。
2. **初始 RAG 的价值也体现在效率和紧预算适应性。** 标准预算下，RAG + Agent 相比纯 Agent，工具调用从 118 降到 82（少 30.5%），已知 token 少 2.7%，P95 从 14.50s 降到 7.73s。紧预算下规则通过分别为 39/40、36/40，自评为 36/40、35/40。
3. **全文方案需要区分容量与质量。** 标准预算下全文规则 38/40、自评 35/40，平均每题约 3.27 万 token；紧预算下 40 题均超限，0 个预算内成功。这个 0 不表示 40 条回答的内容全部错误。总 token 由 usage 事后核验，超限请求的实际已知用量仍记录，没有伪装成账单硬上限。
4. **RAG 单次调用便宜，但这组检索与提示的回答覆盖不足。** 标准预算下平均每题约 1,350 token，规则 25/40、自评 15/40。该结论针对本组固定的 6 片段检索，不涵盖更强重排、查询改写或更大检索预算。

## 两类评分应并列保留

共有 32 条评分分歧：31 条规则通过但自评未通过，1 条相反。这些是待复核分歧，不能未经人工核验就宣称规则或裁判一定正确。

- `sqlite-04 / agent_only / standard`：回答同时写了“34:12（2072–2080 秒）”，34:12 实际是 2052 秒。规则只检查未修改前端的事实而通过，自评检查附加时间后未通过。
- `resume-08 / agent_only / tight`：回答明确说明工具 DAU 未提供，并把视频中简历建议的时间列作依据；规则的数字禁止模式命中了 `日活多少”,约6`，把时间表达也拦下。自评认为这是有依据的拒答而通过。这说明大模型评审也可以帮助发现规则误扣。

## 完整性与开销口径

- 320 条回答记录全部保留：272 条预算内有效回答、43 条超预算、5 条 HTTP 429。未补跑替换失败题。
- 正式裁判对 272 条有效回答逐条评分，48 条已知答题失败直接计失败；最终 320 条判定中未知评分为 0，正式裁判没有接口或格式失败。
- 正式回答已知 token 3,683,818；正式裁判 token 9,580,943。答题有 5 次请求缺 usage；探针与早期诊断消耗不混入这些正式指标，不推算货币费用。
- 早期并发评分出现限流、2,048-token 裁判输出被推理耗尽，故正式评分统一改为答题后单独执行、8,192-token 输出额度；旧诊断已归档，未混合裁判口径。
- 相比 2026-11-05，模型与统一编排均发生变化，不能把旧 72.5%/92.5% 和本轮数字当同配置的前后提升。
- 小规模固定题集、单次运行和未经人工校准的同模型自评，不支持泛化或统计显著性结论。
