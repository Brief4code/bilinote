# 视频问答四组架构评测报告：Standard 标准预算

> 评测日期：2026-11-10。回答与评审均使用 Tongji API 的 `DeepSeek-V4.1-Flash`。本报告仅汇总 standard 的 160 条回答，不包含其他预算、接口探针或联调诊断的结果与消耗；所有表格均从实际记录重新汇总，没有重新调用模型。

## 1. 结论速览

在本次 **5 段视频、40 道固定题**上，RAG + Agent 的规则评审通过率为 **100.0%（40/40）**，大模型评审通过率为 **95.0%（38/40）**。

- 相比单次 RAG：补查材料后，规则通过数由 25 增至 40，大模型评审通过数由 15 增至 38，但答题 Token 与平均耗时也增加。
- 相比纯 Agent：两者规则结果同为 40/40；RAG + Agent 工具调用少 30.5%，模型请求少 22.8%，P95 耗时少 46.7%。初始检索的主要收益体现在减少补查和长尾等待。
- 相比全材料上下文：RAG + Agent 的已知答题 Token 少 82.7%，且本轮两种评审的通过数均更高。

**大模型评审属于同模型自评，尚未经人工校准，不是独立模型或人工准确率。** 下文的“大模型评审通过率”均使用这一口径。纯 Agent 与 RAG + Agent 的自评仅差 1 题，不能据此推导稳定的泛化优势。

## 2. 比较方案与共同条件

### 2.1 四组架构

| 方案 | 回答前得到的材料 | 能否主动调用工具 | 本组要验证的问题 |
| --- | --- | --- | --- |
| 全材料上下文 | 完整 MD 总结、全部转录及片段时间、视频元信息 | 否 | 一次给全材料，能否直接答好？ |
| RAG | 初始检索得到的 6 个片段 | 否 | 只依靠固定检索，能答到什么程度？ |
| 纯 Agent | 不提供初始检索片段或完整材料 | 是 | 模型能否自己决定查什么、找到答案？ |
| RAG + Agent | 与 RAG 相同实现取得的初始片段 | 是 | 初始检索能否减少补查，并改善回答质量与效率？ |

“全材料上下文”就是旧报告中的“全文 + LLM”：**它不是只输入总结 MD，也没有直接让模型观看视频。** 仅提供总结 MD 的方案没有在本轮单独评测。

两种 Agent 可用的工具相同：查询原始转录、读取笔记、获取视频元信息，均使用生产实现。单次转录查询最多返回 50 条片段，笔记工具最多返回 5,000 个字符；“全材料上下文”组则不截断材料。初始 RAG 的配额为元信息 1 片段、MD 2 片段、转录 3 片段。

四组采用共同回答提示与统一评测循环，不修改生产问答服务；这是一项受控架构实验，不等同于生产默认请求的完整端到端测试。

### 2.2 Standard 的共同上限

| 项目 | 每题上限或设置 |
| --- | --- |
| 模型 / 端点 | `DeepSeek-V4.1-Flash` / `https://agi.tongji.edu.cn/v1` |
| 累计总 Token | 65,536，包含每次请求的输入与输出 |
| 累计输出 Token | 8,192，包含供应商计入 completion 的推理 Token |
| 单次输出 Token | 4,096 |
| 答题时间 | 180 秒 |
| 模型请求 | 最多 4 次 |
| 工具执行 | 最多 9 次、最多 3 轮 |
| 其他条件 | 温度 0、空历史、每题每配置运行 1 次，答题 worker 数为 2 |

同预算指各组使用相同上限，不要求实际花完额度。总 Token 在供应商返回 usage 后核验；提交前不能精确预知输入 Token，因此它是预算内成功条件，不是账单硬上限。本报告范围没有超预算题。

## 4. 两种评审分别如何判通过

### 4.1 规则评审：程序按固定规则检查，不调用大模型

程序先统一大小写、全半角和空白，再检查预先标注的事实组、时间和禁止模式。同一答案在同一版规则下会得到确定结果。

| 检查项 | 判定方法 | 例子 |
| --- | --- | --- |
| 关键事实组 | 每一组至少命中一种允许表达，所有组都满足 | 字段错误题必须同时命中 txt 和 422 |
| 同义表达 | 同一组允许多个表达，命中其中一种即可 | 前20% / 百分之二十 |
| 原文与时间 | 检查指定原句；时间题要求显式时间落入参考起点 ±2 秒 | 922秒、15:22 可匹配 921.92 秒 |
| 无答案题 | 命中“未提供”等拒答表达，并且不命中预设数字编造模式 | 不能先说未提供，再编造 DAU |
| 无效结果 | 空白、截断、请求失败、超预算都计失败，并保留分母 | 429 不补跑替换 |

规则评审不是通用语义判断。例如按钮题当前只检查 Try it out 与 Execute 两个词，程序没有检查顺序；关键词也可能出现在否定或错误关系中。它衡量的是“固定规则通过率”，不能直接称作语义准确率。

证据是否进入上下文另行统计，不是规则通过的必备条件；命中关键词也不自动证明引用可靠。

### 4.2 大模型评审：基于参考答案与完整材料检查语义

使用同一 `DeepSeek-V4.1-Flash` 的新请求担任裁判，不沿用原回答对话。输入包括问题、参考答案、完整冻结材料和候选回答；隐藏架构名称、预算标签、规则结果、耗时和工具轨迹。

| 维度 | 核验内容 | 评分范围 |
| --- | --- | --- |
| 正确性 | 事实、对应关系、否定、顺序、数字及单位是否正确 | 0～4 |
| 完整度 | 是否覆盖题目要求的各个部分 | 0～4 |
| 材料支持 | 引文、时间和附加主张是否由材料支持 | 0～4 |

4 分表示完全满足，3 分表示基本满足但有小问题，2 分表示重要遗漏或部分错误，1 分表示主要错误，0 分表示没有有效回答。

**通过条件：正确性＝4，完整度≥3，材料支持≥3，没有关键错误，而且材料足以裁定。不是三项平均分达标。**

裁判同时检查回答主动附加的时间和事实，而不只检查参考答案中的关键词。原话定位优先参考转录片段时间，不把 MD 章节起点直接当成具体句子的出现时间。

已知答题失败直接计失败，不再请求裁判；裁判请求/格式失败或材料不足以裁定则标为未知。本范围共实际评审 158 条有效回答，另 2 条答题请求失败直接计失败，未知评分为 0。裁判输出额度统一为 8,192 Token，其耗时与用量不计入答题指标。

裁判看到完整材料，而 RAG 答题时只看到初始片段。因此，因检索不足而谨慎拒答也可能被判“未完成任务”；这与捏造答案应区分，不能把每条未通过都直接叫作幻觉。

## 5. 结果表：通过率与答题耗时

### 5.1 总体结果

两种通过率均以每组全部 40 题为分母，包含请求失败。

| 方案 | 规则评审通过 | 大模型评审通过（同模型自评） | 平均耗时（秒） | P50（秒） | P95（秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全材料上下文 | 38/40（95.0%） | 35/40（87.5%） | 3.90 | 3.02 | 8.10 |
| RAG | 25/40（62.5%） | 15/40（37.5%） | 2.94 | 1.92 | 7.30 |
| 纯 Agent | 40/40（100.0%） | 37/40（92.5%） | 5.36 | 3.40 | 14.50 |
| RAG + Agent | 40/40（100.0%） | 38/40（95.0%） | 3.48 | 2.84 | 7.73 |

全材料上下文和 RAG 各发生 1 次 HTTP 429，均留在分母中；纯 Agent 与 RAG + Agent 没有答题请求失败。本范围没有截断或超预算失败，正式裁判没有接口/格式失败。

P50 是中位数；P95 是耗时的第 95 百分位，反映较慢那一端的响应速度。RAG + Agent 的 P95 为 7.73 秒，表示本组约 95% 问题在此时间内完成，不是最长耗时。每组只有 40 个样本，分位数使用线性插值，不能直接当线上 SLA。

计时包含检索、模型请求和工具执行，不包含首次建索引、Embedding 预热、客户端创建、任务排队及事后评审。

## 7. RAG + Agent 的优势与代价

### 7.1 相比单次 RAG：补齐检索不足，而不是只扩大答案篇幅

规则通过率从 62.5% 升至 100.0%，提高 **37.5 个百分点**；同模型自评从 37.5% 升至 95.0%，提高 **57.5 个百分点**。标注证据可得数从 16/35 增至 34/35。

例如字段错误题中，单次 RAG 没检索到 txt 与 422，只能说明无法据当前片段回答；RAG + Agent 通过查询转录取得细节，最终同时通过规则与大模型评审。收益来自可以继续取得材料。

代价是已知答题 Token 约为单次 RAG 的 **4.19 倍**，平均耗时从 2.94s 增至 3.48s（约增加 18.6%）。因此不能称为相对单次 RAG 的全面降本。

### 7.2 相比纯 Agent：初始检索减少补查与长尾等待

| 指标 | 纯 Agent | RAG + Agent | 本轮变化 |
| --- | ---: | ---: | --- |
| 规则通过 | 40/40 | 40/40 | 持平 |
| 同模型自评通过 | 37/40 | 38/40 | 多 1 题 |
| 工具执行 | 118 次 | 82 次 | 少 30.5% |
| 模型请求 | 114 次 | 88 次 | 少 22.8% |
| 已知答题 Token | 232,384 | 226,099 | 少 2.7% |
| 平均耗时 | 5.36s | 3.48s | 少 35.0% |
| P95 耗时 | 14.50s | 7.73s | 少 46.7% |

RAG + Agent 在 **11/40 题**中没有调用工具，直接依据初始材料给出了最终回答；纯 Agent 的 40 题都使用了工具。本轮数据支持把初始 RAG 看作查询的起点，以减少不必要的主动检索，而不是把它视为可有可无的环节。

### 7.3 相比全材料上下文：减少反复输入长材料

全材料上下文每题平均约 32,676 Token，RAG + Agent 为 5,652 Token，已知总用量少 **82.7%**。同时，规则通过为 40/40 对 38/40，自评通过为 38/40 对 35/40。

这支持按需读取材料的方案在本题集上更节省输入，但不能推广为“给更多上下文一定更差”，也不能代替仅提供总结 MD 的独立对照。全材料组还包含 1 次限流失败，其分数差不全是内容质量差。

## 8. 代表性案例与仍然存在的问题

### 8.1 查到两个事实，才算完成任务

题目：请求示例把 text 错写成哪个字段？FastAPI 返回什么状态码？

- RAG：说明当前片段没有错写字段和状态码，未完成问题，规则与大模型评审均未通过。
- RAG + Agent：回答 txt、422，并给出转录中的对应原句，三项自评分均为 4，两个评审均通过。

谨慎拒答不等于捏造，但当材料实际存在答案时，整条问答链路仍然没有完成任务。

### 8.2 时间定位正确的正例

题目：“项目中90%以上的代码”从什么时候开始说？参考起点为 921.92 秒。RAG + Agent 回答“922 秒，即 15:22”，位于 ±2 秒容差内，三项自评分均为 4。

### 8.3 规则通过，但附加时间换算错误

题目：SQLite 重构时是否修改前端？纯 Agent 正确回答“没有”，但附带写出“34:12（2072–2080 秒）”。34:12 实为 2052 秒，前后不一致。

规则只检查“没有”“前端”等事实而通过；裁判给出正确性 3、完整度 4、材料支持 3，因此未通过。这个例子说明只命中主结论不足以证明整段回答可靠。

### 8.4 RAG + Agent 自身的两条未通过

## 9. 结论边界与后续改进

- **样本较小且内容集中。** 只有 5 段视频，4 段来自同一系列技术课程；每配置每题只运行一次，没有按新视频划分的独立留出集。
- **参考材料不是人工真值。** 笔记与 ASR/OCR 可能存在遗漏、误识别或冲突，参考答案和裁判都受材料质量约束。
- **评审不是独立模型验收。** 回答与裁判使用同一模型，分数和理由仍可能有偏差；严格通过阈值不能替代人工校准。
- **基线范围明确。** RAG 是固定的 6 片段单次检索，没有覆盖更强重排、查询改写、迭代检索或仅完整 MD 等其他方案。
- **时间不是线上全链路。** 未覆盖冷启动、排队、用户鉴权、多轮历史和更高并发，不应把本次 P95 当生产 SLA。
- **预算不是精确账单硬限额。** 总 Token 在 usage 返回后核验；缺 usage 的失败请求存在未知消耗，不推算货币费用。

下一步优先做三件事：复核本范围 18 条评分分歧并抽查通过答案；将回答中的时间与引文绑定到实际转录片段，减少模型自由换算；在新视频留出集上重复比较，并考虑不同模型裁判或双人标注校准。
