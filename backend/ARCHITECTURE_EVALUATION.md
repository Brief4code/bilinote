# 四组架构、双重评分与统一预算评测

本协议独立于 [2026-11-05 历史实验](benchmark_records/2026-11-05-agent-eval/REPORT.md)。沿用固定的 5 段视频、40 题及 v1.1 规则，不替换旧答案或旧指标。

## 实验矩阵

| 配置 | 初始输入 | 可调用工具 |
| --- | --- | --- |
| `full_context` | 完整冻结笔记、转录与安全元信息，不截断 | 无 |
| `rag` | 真实向量检索的 6 个片段 | 无 |
| `agent_only` | 无初始检索或预先提供的笔记 | 生产的三个材料查询工具 |
| `rag_agent` | 与 RAG 相同的检索实现和片段 | 相同三个工具 |

四组使用相同模型、温度、材料版本、问题和共同回答提示。初始检索不是专门针对答案构造的片段；纯 Agent 可以用工具主动读取同一份材料。原始转录的 start/end、笔记和视频元信息均属于可用材料。全文组不按答案选择片段，不静默截断。

为控制变量，四组使用评测脚本中的统一循环，复用真实 `VectorStoreManager.query()`、`_build_context()` 和 `execute_tool()`。不修改生产 `chat_service.chat()`，也不声称本实验是生产配置的原样重跑。报告对两个 RAG 组的实际初始文本和元信息进行一致性校验。

默认从本地 Cline 的 `~/.cline/data` 读取 OpenAI 兼容端点、act 模型和凭据。当前为 Tongji `https://agi.tongji.edu.cn/v1`、`DeepSeek-V4.1-Flash`。凭据只在内存中用于认证，不写入报告或生产数据库；缺少 Cline 凭据时直接报错，不回退到其他供应商。保存供应商返回的实际模型名，供检查网关映射。

回答与裁判都使用当前 Tongji 模型时，必须显式设置 `--allow-self-judge`，元数据和报告标注为**同模型自评**，不能称为独立模型验收。仍然隐藏架构、预算和规则结果。若需不同模型的裁判，可用 `--model` 选择同一端点实际支持的其他模型。

## 两档预算

每个问题、每种配置、每次重复都有独立额度；不会在不同题之间共享余额。

| 档位 | 总 token | 累计输出 token | 单次输出 token | 时间 | 模型请求 | 工具执行 | 工具轮数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| tight | 16,384 | 2,048 | 1,024 | 90 秒 | 4 | 9 | 3 |
| standard | 65,536 | 8,192 | 4,096 | 180 秒 | 4 | 9 | 3 |

总 token 包含每次请求的完整输入与输出，历史消息的重复输入会再次计入。供应商计算的 completion tokens（包括其归入该字段的推理 token）计入输出额度。

每次调用前限制剩余输出额度、请求数、工具执行数和剩余时间，SDK 自动重试关闭。最后一次模型请求关闭工具，要求基于已有证据收束。一轮请求多个工具也不能绕过累计工具次数上限。材料读取/检索计时，首次索引构建、Embedding 预热、客户端创建及任务排队不计入题目时间。

**总 token 是基于响应 usage 的预算内成功条件，不是账单硬上限。** 供应商未提供本地精确输入计数能力，提交前无法准确知道当前 prompt tokens；最后一个请求可能使实际支出超限。收到响应后立即检查，超限保留已知消耗及弃用答案，停止后续调用并计失败。同步报告超限数和实际用量，不将超限回答计为预算内通过。

缺 usage 时不猜测为零，也不继续调用；标记不可核验。空回答、截断、异常、超时及超预算均留在分母。全文超出供应商上下文或总预算也按失败记录，不能偷偷改为摘要或截断输入。四组拥有相同上限，不要求实际花完额度。

收到明确的 `insufficient_quota` 后，停止排队中的请求，保留已经发生的调用与部分结果，并标记运行未完成；不会自动改用其他模型或更改计费方式。

## 两种评分

1. **规则评分**：复用 v1.1 的事实组、禁止模式及时间容差，保留历史口径。规则的关系、否定和顺序盲区仍存在；该指标不等于全面语义正确率。
2. **大模型评分**：裁判获得问题、参考答案、完整冻结材料和候选回答，隐藏架构、预算标签、工具轨迹、耗时及规则结果。每条答案独立评分，顺序固定种子打乱；这不是成对偏好评测。

裁判维度是正确性、完整度、材料支持，各 0–4 分；核心正确性为 4、另两项至少 3、且没有关键错误时通过。显式检查实体关系、先后顺序、否定、数字/单位、引文和定位；时间题沿用数据集容差。

裁判默认输出上限为 8,192 token（包括供应商计入 completion 的推理 token），与答题预算分开。Tongji 试运行表明 2,048 token 可能被推理耗尽而没有 JSON；这类诊断不混入正式裁判结果。为减少共享端点并发限流，当前完整实验先答题、后评分。

答题阶段已失败的结果直接记为失败，不浪费裁判请求。裁判网络/格式错误和材料不足以裁定分别记录为未知，不转成“回答内容错误”。报告给出确定通过数、未知数及通过率上下界，列出与规则结果分歧的答案。裁判使用全部材料，超过字节限制时整体拒绝启动，不能只给裁判看到有利片段。

裁判尚未经人工校准，不能宣称是真值。参考答案和材料仍来自笔记/ASR/OCR，不保证与原视频逐字一致。裁判的 token、耗时和异常单独统计，不加入回答方案的预算或效率指标。

## 执行与复现

先在仓库根目录使用完整后端 Python 环境验证材料（只复制到隔离目录，无模型请求）：

```bash
python backend/scripts/evaluate_architectures.py \
  --output backend/data/agent_eval/architectures-validation \
  --validate-only
```

真实执行 40 题 × 4 组 × 2 档，共 320 条回答；每条回答最多 4 次模型请求。默认每题每配置运行一次，不作统计显著性声明。需要重复时显式设置 `--repeats 3`，保持全部失败记录：

```bash
python backend/scripts/evaluate_architectures.py \
  --output backend/data/agent_eval/architectures-main \
  --provider-source cline --workers 2

python backend/scripts/judge_architectures.py \
  --run backend/data/agent_eval/architectures-main \
  --output backend/data/agent_eval/architectures-judge \
  --provider-source cline --allow-self-judge --workers 2

python backend/scripts/report_architectures.py \
  --run backend/data/agent_eval/architectures-main \
  --judge-run backend/data/agent_eval/architectures-judge \
  --output backend/benchmark_records/architectures-main
```

`--case-id resume-04` 等参数用于新目录中的独立诊断。仅有部分题目的运行会显式标为诊断，不能当完整结果。`--budgets tight` 或 `--modes rag agent_only` 可选子实验。裁判支持 `--validate-only` 检查完整输入而不联网；报告器不调用模型。

`--cline-dir` 可以指定其他 Cline 数据目录。`--validate-only` 不读取密钥。兼容历史数据库供应商的入口需要显式传入 `--provider-source database --provider ... --model ...`，当前 Tongji 实验不使用该入口。

回答运行已开始落盘后，可给裁判加 `--follow`，让它逐条消费完整记录以减少等待。它会校验每条回答没有被修改，等整个矩阵完整后再次核验，并写入最终结果文件哈希；未完成的裁判运行不能用于正式报告。`--follow-timeout` 默认 7200 秒，超时保留部分结果但不标为完成。

若明确只交付受限结果，可给报告器加 `--allow-partial-judge`。它仍要求回答矩阵完整，校验已有裁判记录的答案哈希；未评分的有效回答标为未知，已知无效回答计失败，并在报告开头提示裁判未完成。不得将这种报告称为完整大模型验收。

所有运行目录必须为空；不得覆盖已有实验。固定保存题集、材料快照及哈希、模型设置、预算、脚本哈希、共同提示哈希、逐题结果、完整工具返回及请求 usage。报告/裁判拒绝缺题、重复记录、题目或预算变化、快照变化、评分与原始记录不一致，以及两个 RAG 组收到不同初始证据。

回答运行在 `source/` 保留脚本和生产检索/工具实现快照，裁判目录保留其脚本；源码快照用于核验记录的 SHA-256，后续仓库修改不会冒充当时的运行代码。

生成 `REPORT.md`、`summary.json` 和 `answers.jsonl`；报告包括每档预算内的规则/模型评分、合规数、P50/P95、token、工具调用、错误分类，JSON 另含题型结果、与 RAG 的成对规则变化和规则/裁判分歧。完整转录与工具轨迹留在 Git 忽略的运行目录；不自动发布。

## 隔离与外部调用内容

只读本机供应商配置及选定视频材料，复制必要笔记/转录/公开视频元信息到独立目录；不读取聊天历史，不修改生产数据库、用户或原向量索引。API key 只用于认证，不写入结果或 prompt。

真实回答请求会向所选供应商发送问题、模型输入片段或全文、以及后续工具结果。裁判请求还会发送参考答案、候选回答和完整冻结材料。费用按供应商实际计费，报告只记录 token，不虚构货币成本。
